# MySQL 8.0.41 并行查询差分测试平台设计

日期：2026-07-12

状态：已由用户批准，等待书面规格复核

目标版本：开源 MySQL 8.0.41 与基于 MySQL 8.0.41/InnoDB 的自研并行查询引擎

## 1. 产品目标

构建一个可 7×24 小时运行的 MySQL SELECT 差分测试平台，同时支持：

1. **正确性模式**：在三个隔离且同规格的服务器上执行同一条查询，比较开源基准、自研并行关闭、自研并行开启三路结果或错误。
2. **性能模式**：在三个服务器上并发执行同一条 `EXPLAIN ANALYZE FORMAT=TREE` 查询，比较并行开启节点相对两个参考节点的执行时间。
3. **覆盖驱动生成**：随机生成兼容的数据库、表、列、索引、数据和只读 SELECT；长期运行时优先补齐欠覆盖特性。
4. **完整复现**：每轮创建并永久保留同名数据库，异常立即追加报告，并保存可独立重放的用例包。
5. **本地控制台**：通过 Python 内核、FastAPI 控制面和 React/TypeScript SPA 启动任务、查看实时状态、筛选异常并重放用例。
6. **12 小时主动补全验收**：连续 12 小时在网上发现 MySQL 8.0.41 查询形态，检查生成器是否可达；发现缺口后以测试驱动方式补齐，再继续搜索。

## 2. 非目标与边界

- 查询阶段只生成只读 SELECT query expression，不生成会修改数据的 DML，不生成锁定读、`INTO`、用户变量赋值或可能有副作用的存储函数/UDF。
- 正确性与性能模式互斥；正确性可多线程，性能独占三台服务器并使用单工作线程。
- warning 不参与通过/失败判定，但允许作为诊断信息保存。
- 配置指纹不一致只警告并继续；所有 finding 必须携带三节点配置指纹。
- 正式性能测量每节点只执行一次，因此超过阈值只称为 `PERF_ALERT`，不称为统计学确认的回归。
- 性能模式不验证缓存是否真正热，报告必须标记 `cache_state_unverified`。
- 本地三个开源实例可以验证平台和 oracle，不能替代自研并行执行器的最终验收。

## 3. 已确认的三节点拓扑

三个服务器资源隔离、硬件规格一致、账号密码一致：

- `baseline`：开源 MySQL 8.0.41。
- `custom_off`：自研引擎，全局关闭并行查询。
- `custom_on`：自研引擎，全局开启并行查询。

全局开关不在测试过程中切换，而由固定服务器角色表示。配置可提供 `role_probe_sql` 与预期值；探针缺失或不匹配时警告并继续。

程序只生成一份确定性用例包，再把完全相同的 DDL、DML、数据文件和 SELECT 分发到三台服务器。每轮在三节点创建同名唯一数据库，数据库名包含模式、时间、worker、轮次和 seed。数据库不自动删除。

临时表受 MySQL 会话语义约束，连接结束后无法永久保留。临时表场景仍永久保留承载数据库和完整复现包；人工 replay 时由复现包在固定会话中重建临时表。

## 4. 总体架构

采用模块化单仓库：

- **Python 3.11+ 测试内核**：配置、生成、执行、oracle、性能校准、报告和 replay。
- **CLI**：直接运行测试内核，也可控制本地 API 服务。
- **FastAPI 控制面**：管理任务状态、查询报告、SSE 事件流和前端静态资源。
- **React + TypeScript SPA**：Vite 构建，使用 REST + SSE；生产构建由 FastAPI 托管。
- **任务监督器**：每个 run 使用独立子进程；正确性 run 内部使用线程池，性能 run 单线程。
- **追加式存储**：JSONL 与逐用例目录是事实来源；可重建的 SQLite 读模型仅用于前端检索。

任务状态机：

`queued → starting → running → stopping → stopped/completed/failed`

服务重启后无法确认的任务进入 `recovering` 或 `orphaned`，不得伪装成正常完成。启动、停止和 replay API 必须幂等。

## 5. 配置与命令

配置使用 YAML；主机和非敏感参数可写文件，密码只从环境变量读取。密码不得进入仓库、报告、日志、复现 SQL 或 Git 历史。

主要命令：

- `run --mode correctness`
- `run --mode performance`
- `serve`
- `doctor`
- `replay <case_id>`
- `report`
- `cleanup`

`run` 默认无限运行，同时支持 `--rounds`、`--duration`、`--seed` 和优雅停止。

`serve` 启动 FastAPI 并托管构建后的 React SPA，可配置是否自动打开本机浏览器；用户可在前端直接创建和控制两种 run。

预检验证当前模式所需的建库、建表、临时表、插入、索引、查询、`LOAD DATA LOCAL`、状态读取和终止本账号查询能力。缺少必需权限时拒绝启动；普通配置差异只警告。

## 6. 覆盖驱动 Schema 生成

纯随机不能保证稀有特性覆盖，因此采用“覆盖欠债 + 场景内随机”策略。每个启用特性默认至少命中 10 次才完成一个覆盖周期，累计计数永久保留。

每轮选择一个兼容性场景，避免生成官方禁止的组合：

1. 普通持久 InnoDB 表。
2. 分区表。
3. 外键图。
4. 临时表专用会话场景。
5. FULLTEXT 场景。
6. SPATIAL 场景。
7. JSON 多值索引场景。
8. 可选的物理/极限边界场景。

兼容矩阵至少编码：

- 临时表不能分区、不能带外键，且同一临时表不能在一个查询中重复打开。
- InnoDB 分区表不能带外键、FULLTEXT 或空间列。
- 分区表所有唯一键必须包含全部分区列。
- 外键两侧类型、符号、字符集和排序规则必须兼容，并存在正确的左前缀索引。
- BLOB/TEXT 普通索引必须使用前缀；函数、空间、全文、多值与外键 key part 的限制分别建模。
- 索引长度必须根据 page size、row format 和字符集最大字节数计算。

正确性模式默认每轮：

- 10 个 worker。
- 1–8 张表。
- 每表 2–16 列。
- 每表 10–1,000 行。
- 1,000 条查询。

全部参数可设为固定值或范围。

## 7. 数据生成

同一轮只生成一次数据，再并发加载三节点。加载后校验表结构、行数和数据摘要；三路全部成功才进入查询阶段。三路同样的前置错误视为生成器拒绝样本并重新生成；部分服务器失败记录为 `SETUP_MISMATCH`。

数据采用可配置混合分布：

- 类型边界、零值、空值和空字符串。
- 均匀分布。
- Zipf 热点。
- 低基数重复。
- 高/低 NULL 比例。
- 唯一值。
- 列间相关。
- FK 命中、空值和未引用分布。
- Unicode、二进制和特殊字符。

列声明覆盖合法最小到最大范围。实际 LOB/JSON 数据分层：普通轮次单值默认不超过 64 KiB；大值场景可配置到 `max_allowed_packet` 的安全上限，不在主循环中随机分配 GiB 级单值。

## 8. SELECT 生成器

查询以类型感知 AST 生成，而不是字符串片段拼接。默认复杂度预算：

- 1 个主要特性，最多 2 个辅助特性。
- 最多引用 4 张表。
- 嵌套深度 3。
- CTE 2 个。
- 集合分支 3 个。
- 投影列 12 个。
- 条件节点 12 个。

限制均可配置。正确性模式默认 5% 查询进入自由随机路径，另有 5% 主动负向变异；性能模式两者默认均为 0。

覆盖目录包括：

- 基础 SELECT、ALL、DISTINCT、WHERE、ORDER BY、LIMIT。
- INNER/CROSS/LEFT/RIGHT/NATURAL/USING 与等值、非等值 Join。
- 标量、行、相关与非相关子查询；IN、EXISTS、ANY、ALL。
- 派生表与 LATERAL。
- 普通 CTE、CTE 链与受控递归 CTE。
- UNION、INTERSECT、EXCEPT 的 ALL/DISTINCT 形式。
- GROUP BY、HAVING、ROLLUP、精确聚合和 DISTINCT aggregate。
- 命名/内联窗口、ROWS/RANGE frame 与确定性 tie-breaker。
- JSON 标量函数、JSON_TABLE、CASE/IF 和类型兼容的确定性函数。
- 与 schema 匹配的全文、空间和索引查询。
- 正确性模式中的低比例合法 optimizer hints。

两种模式都禁用 RAND、UUID、当前时间、会话状态、文件、锁、SLEEP/BENCHMARK、用户变量、存储函数、UDF 等非确定或可能有副作用的表达式。性能模式默认禁用计划强制 Hint，只保留超时保护。

## 9. 正确性 Oracle

三路全部成功时比较：

- 列数量、列名、MySQL 类型、signed/binary 属性和 NULL 元数据。
- 类型化行的多重集合，保留重复次数，不依赖服务器返回顺序。
- SQL 仍尽量追加 `ORDER BY 1,2,...`，但它不是唯一 oracle。
- 所有 LIMIT、top-N 与窗口顺序必须具有可证明唯一的 tie-breaker；无法证明时拒绝样本。

结果默认保护上限：10,000 行和 32 MiB，均可配置。生成阶段估算，执行阶段再次保护。

值比较：

- 整数、DECIMAL、字符、二进制和日期时间严格比较。
- FLOAT 默认绝对误差 `1e-6`、相对误差 `1e-5`。
- DOUBLE 默认绝对误差 `1e-12`、相对误差 `1e-9`。
- JSON 对象键规范化，数组顺序保留。
- 空间值比较 SRID 与 WKB；空间关系优先投影布尔或精确标量。

浮点容差不是传递关系，不能通过简单舍入后哈希实现。比较器先按所有非浮点字段和类型元数据分组，再在组内对浮点向量做确定性一对一匹配；必须消耗相同数量的行才能判定多重集合相等。

三路全部报错时比较 `errno + SQLSTATE + 规范化错误文本`，只去除连接 ID、主机地址等易变字段，同时保存完整原文。部分成功、部分报错或错误结构不同均为 finding。

warning 不参与 verdict。

正确性查询默认 15 秒超时。三路全部超时记为 `OVER_BUDGET`；部分超时记为不一致。watchdog 使用独立控制连接执行 `KILL QUERY`。

## 10. 性能模式

性能模式使用热缓存意图但不验证缓存状态，主要面向 CPU 密集型查询。

默认规模：

- 单 worker。
- 1–4 张表。
- 每表 4–16 列。
- 初始每表 100,000 行。
- 按倍数增长，单表默认最多 50,000,000 行。
- 最多 8 轮规模校准。
- 每轮默认 100 条正式查询。

每个查询模板带工作量旋钮：扫描行数、range 选择率、Join build/probe 规模与扇出、聚合输入与分组数、排序行数与键宽、窗口 partition/frame。先用计划估算初始规模，再在 `baseline` 与 `custom_off` 上对候选规模默认试跑 3 次取中位数。只有两端都进入 5–30 秒才冻结数据、SQL 和 seed。

正式阶段：

1. 三路 barrier 同时放行。
2. 每节点执行一次 `EXPLAIN ANALYZE FORMAT=TREE`。
3. 主计时取顶层 iterator `actual time=a..b` 的 `b`。
4. 客户端 monotonic wall time、Performance Schema 和完整计划仅作诊断。
5. 60 秒触发 MAX_EXECUTION_TIME 与独立 watchdog KILL。

默认回归阈值 `0.20`，可配置。满足任一条件即记录 `PERF_ALERT`：

- `custom_on >= custom_off × (1 + threshold)`。
- `custom_on >= baseline × (1 + threshold)`。

`custom_on` 超时且任一参考节点完成时记录 `PERF_ALERT`；三路全部超时为 `OVER_BUDGET`；参考节点正式执行意外超时为 `CALIBRATION_DRIFT`。被终止后的部分 TREE 计划不得当作完成耗时。

三路实际开始偏差超过默认 100 ms 时标记 `TIMING_UNRELIABLE`，保存全部数据但不触发正式性能告警。

## 11. 报告、复现与留存

每个异常立即：

1. 追加写入按天分片的 JSONL。
2. `fsync` 后才对外报告成功。
3. 创建独立用例目录。
4. 原子更新可重建的查询索引和 HTML 视图。

通过查询只保存列元数据、行数、类型化强哈希、耗时和覆盖标签。异常保存三路完整压缩结果、首个差异、差异统计、完整错误、计划、配置指纹、数据库名、seed、setup SQL、query SQL 和 replay manifest。

finding 不停止当前线程或整轮；基础设施故障除外。任一节点断连、重启或不可用时记录 `INFRA_ERROR`，暂停相关工作，指数退避，三节点恢复后继续。该次查询不参与判定。

## 12. 前端控制台

前端仅绑定本机 `127.0.0.1`，暂不实现账户登录。页面包括：

- 总览：服务、三节点、任务、吞吐、覆盖和近期异常。
- 新建任务：模式、seed、并发、轮次、查询数量、超时和覆盖策略。
- 任务详情：状态、实时事件、覆盖率、节点状态、停止入口。
- 异常列表：模式、严重度、节点、SQL 特性、错误码和时间筛选。
- 异常详情：SQL、seed、三路结果/错误/计划、配置和产物链接。
- Replay：启动重放、显示逐节点结果和是否复现。
- 历史任务与报告。

REST API 使用 `/api/v1`；实时事件使用带 sequence 的 SSE。前端按 sequence 去重，发现缺口时拉取服务端快照后重新订阅。所有加载区块显式支持 loading、empty、data、stale、error，局部失败不能导致整页白屏。

## 13. 12 小时主动 SQL 形态补全循环

这 12 小时的验收目标不是被动运行现有随机生成器，而是连续主动执行以下闭环：

`网上搜索 → 收集查询形态 → 提取版本化结构签名 → 判断生成器是否可达 → 不可达则测试驱动修改 → 全量回归 → 继续搜索`

必须连续运行满 12 小时；中断时间不计入。每 30 分钟 checkpoint，最后 30 分钟冻结新代码，只继续搜索、验证与整理。

“所有查询形态”在这里定义为：对预先记录且不断扩展的权威来源集合执行尽可能完整的发现，并用来源 manifest、搜索词、版本证据、唯一 signature 数量、未覆盖清单和新增 signature 饱和曲线证明搜索范围。12 小时不能构成对互联网或所有 SQL 组合的数学穷尽证明，系统不得作出这种虚假声明。

来源优先级：

1. MySQL 8.0.41 官方 release notes 与官方手册。
2. 官方 `mysql-server` 仓库 8.0.41 对应 tag/commit 中的 parser 与 `mysql-test`。
3. 官方示例数据库和官方测试语料。
4. 固定 commit 的成熟开源 SQL 测试项目。
5. 博客、论坛和问答只作线索，必须回到官方或源码证据确认 8.0.41 适用性。

任何网页 SQL 只能进入隔离语料区，禁止直接发给 MySQL。系统提取并保存：来源 URL、来源等级、版本证据、抓取时间、内容 hash、许可证和抽象 feature signature。只有生成器根据安全 AST 重新合成并通过只读安全检查的 SQL 才能执行。

signature 至少描述：

- query block 数、嵌套和相关层级。
- CTE/递归、集合操作及括号结合。
- 派生表、LATERAL 和 Join 图。
- 子查询类别。
- 聚合、HAVING、ROLLUP。
- 窗口、frame 和 tie-breaker。
- ORDER/LIMIT。
- 表达式、函数、类型、排序规则。
- 所需 schema、数据分布、索引和基数。

能力状态：

- `covered`
- `latent/unreachable`
- `missing`
- `unsupported-8.0.41`
- `unsafe/out-of-scope`
- `indeterminate`

发现 `missing` 或不可达结构时，必须先新增失败的 signature/reachability 测试，再做最小生成器修改。依次通过安全策略、AST 单测、固定 seed 属性测试、历史回归、本地 MySQL 集成与短 canary 后才允许保留修改。一个缺口一个本地提交；有远端时立即推送。没有远端时允许本地提交并记录待推送状态。

12 小时循环从干净的专用 `codex/...` 分支或 worktree 开始。每个缺口在独立 worktree 中修改，严禁覆盖用户已有的未提交变更；通过门禁后再按顺序集成到本轮 soak 分支。

门禁失败时只撤销本轮未提交补丁，不改写历史。已提交后发现回归使用 `git revert`，禁止 `reset --hard`。

12 小时最终产物：

- 来源 manifest。
- 脱敏 feature-signature corpus。
- 查询形态覆盖矩阵。
- 缺口、拒绝和版本不支持清单。
- 每轮修改、测试、commit 与 push 状态。
- 本地三节点 soak 报告。
- 最终 HTML/JSONL 报告和可复现用例。

## 14. 测试策略摘要

详细测试计划在规格复核后单独编写。发布门禁至少包括：

- 核心 Python 模块行覆盖率 ≥90%，整体分支覆盖率 ≥85%。
- 至少 10,000 个 property 样本无未分类失败。
- 相同 seed、配置和版本生成字节级一致用例包。
- 三个相同开源 MySQL 节点执行至少 50,000 条正确性查询，确认型假阳性为 0。
- 人工注入单节点数据、结果、错误、超时和断连差异，检出/分类正确率 100%。
- timeout 后无遗留查询，节点恢复后无需重启主程序。
- JSONL 在任意写入边界被终止后仍可恢复，已提交事件不丢不重。
- React 单元/组件分支覆盖率 ≥85%；Playwright 覆盖启动、停止、刷新恢复、筛选、详情、replay、报告和故障矩阵。
- SSE 重连不重复计数，序号缺口触发快照恢复。
- 12 小时主动补全循环无崩溃、永久 hang 或持续线性资源泄漏。
