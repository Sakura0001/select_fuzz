# Fuzz 中文报错设计

日期：2026-08-06

## 目标

将 fuzz 运行失败链路中面向操作者的英文提示改为中文，使终端输出能直接说明失败阶段和原因，同时保留底层异常的完整诊断信息。

## 范围

本次只修改 fuzz 运行链路的人类可读文本：

- CLI 顶层 `run` 失败提示。
- fuzz 新批次创建失败提示。
- 等待备节点同步超时提示。
- fuzz 查询生成进程异常退出和预生成失败提示。

不修改以下稳定接口：

- 异常类名，例如 `_GenerationBuildError`、`TimeoutError`。
- MySQL、Python 或连接器返回的原始异常文本。
- JSON 事件字段名及机器可读值，例如 `type`、`error_type`、`query_timeout`。
- `doctor`、`report`、`replay`、`cleanup` 等其他 CLI 命令的提示。

## 输出格式

顶层失败格式：

```text
运行失败：<异常类型>：<中文上下文及原始异常>
```

批次创建失败格式：

```text
fuzz 批次创建失败：数据库[<序号>]=<数据库名>，异常类型=<异常类型>，原始错误=<原始异常>
```

主备同步超时格式：

```text
等待备节点同步超时：已等待 <秒数> 秒；数据库=<数据库名>；最后一次探测异常=<异常类型>：<原始异常>
```

没有探测异常但 GTID 尚不可见时，末段改为：

```text
主节点 GTID 在备节点尚不可见：<GTID 标记>
```

## 兼容性

中文只包裹工具自身生成的上下文。原始异常逐字保留，因此用户仍可按 MySQL 错误码、异常类名和服务端英文文本检索。结构化日志不翻译，已有分析脚本和事件消费逻辑无需修改。

## 测试

测试驱动覆盖以下行为：

1. `select-fuzz run` 失败时输出中文顶层提示，并保留异常类名和原文。
2. 多数据库批次创建失败时，每个失败项包含中文标签、数据库名、异常类型和原文。
3. 备节点同步超时时，两种末因分支均输出中文。
4. 结构化事件字段和值保持原样。
5. 全量测试、Ruff、Mypy 和发行包构建通过。
