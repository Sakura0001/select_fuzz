# MySQL 8.0.22 Fuzz Grammar Compatibility Design

## Goal

Make MySQL 8.0.22 the only production target of the canonical SELECT grammar used by
`select-fuzz`, prevent fuzz readers from flooding the SQL-generation pipeline with
immediately rejected statements, and make any remaining compatibility-error throttling
visible in the existing diagnostics.

## Confirmed decisions

- The canonical SELECT grammar targets MySQL 8.0.22 only. There is no runtime version
  switch and no retained MySQL 8.0.41 grammar profile.
- The scope of the version change is the SELECT grammar asset, its production loader,
  packaging references, directly coupled tests, and production generator wiring. Existing
  historical research and exact-version integration tooling are not rewritten unless they
  directly load the canonical grammar asset.
- `INTERSECT`, `INTERSECT ALL`, `EXCEPT`, and `EXCEPT ALL` are removed because they were
  introduced after MySQL 8.0.22.
- `VALUES ROW(...)`, `TABLE`, and their legal `UNION` combinations remain because MySQL
  8.0.22 supports them. Invalid chains disappear when the post-8.0.22 set operators are
  removed.
- FULLTEXT and SPATIAL query families are not submitted by fuzz mode because the target
  engine does not support them. JSON-dependent candidates are also excluded in fuzz mode
  because fuzz-created schemas do not contain JSON columns.
- Deadlocks, lock-wait timeouts, execution timeouts, and numeric overflows remain valid fuzz
  outcomes. They are recorded normally and do not activate compatibility backoff.

## Architecture

### One canonical 8.0.22 grammar

Rename `catalog/mysql-8.0.41-select.grammar.yy` to
`catalog/mysql-8.0.22-select.grammar.yy` and update the packaged-data mapping and
`SelectGrammar.default()` fallback to the new asset. The module description and directly
coupled tests refer to 8.0.22. No second asset, compatibility enum, or profile selection is
added.

The grammar itself is narrowed at the source rather than filtering generated SQL after the
fact. This preserves deterministic generation and avoids spending generator capacity on a
candidate that is known to be invalid for the target version.

### Grammar removals and restrictions

The canonical grammar makes the following changes:

1. `set_operator` retains only `UNION`, `UNION ALL`, and `UNION DISTINCT`.
2. `select_modifier_list` retains row qualifiers and optimizer hints. The unrestricted
   random combinations containing `HIGH_PRIORITY`, `STRAIGHT_JOIN`,
   `SQL_SMALL_RESULT`, `SQL_BIG_RESULT`, `SQL_BUFFER_RESULT`, `SQL_NO_CACHE`, and
   `SQL_CALC_FOUND_ROWS` are removed. Some of these tokens exist in 8.0.22, but the current
   grammar can place them in nested or set-operation contexts where MySQL rejects them;
   removing the unconstrained branches prevents errno 1234 without adding a second
   context-sensitive SELECT grammar.
3. The hard-coded `_strict_text_column COLLATE utf8mb4_0900_ai_ci = _text` predicate is
   removed. A schema-aware collation renderer is outside this fix; removing the branch
   prevents combining an `utf8mb4` collation with an `utf8/utf8mb3` expression.
4. The remaining syntax and deterministic function registry must be audited against the
   8.0.22 boundary. A production alternative or function introduced after 8.0.22 is removed
   rather than guarded by a version switch.

### Fuzz query-family exclusions

`RandomGrammarQueryGenerator` accepts an immutable set of excluded schema families and
passes it through to `GrammarQueryGenerator.generate()`. Both production construction
paths use the same `frozenset({"json", "fulltext", "spatial"})`:

- the in-process generator used during prewarming and by the inline pipeline;
- the generator constructed inside every `ProcessQueryPipeline` worker.

This keeps prewarming and steady-state execution semantically identical. The grammar hooks
can remain available to non-fuzz schema profiles, but fuzz mode never wastes retries trying
to bind column families absent from its generated schemas.

## Compatibility-error backoff

Source-side removal is the primary fix. A bounded per-reader guard prevents any remaining
immediately rejected compatibility pattern from recreating the feedback loop.

- Compatibility errnos are `1064`, `1234`, `1235`, and `1253`.
- The first consecutive compatibility error waits 10 ms. Each consecutive matching error
  doubles the wait up to 250 ms.
- A successful query or any non-compatibility result resets the streak.
- Errnos `1205`, `1213`, and `1690`, client/watchdog timeouts, connection-loss errors, and
  generator-side candidate rejection do not use this backoff.
- Waiting uses the run stop event, so Ctrl+C, duration expiry, generation refresh, and
  service shutdown interrupt it immediately.
- The long-lived MySQL connection remains open. A connection can therefore briefly appear
  as `Sleep`, but the delay is bounded and the application stage explains why.

The 10 ms and 250 ms bounds are normal `FuzzConfig` settings with safe defaults so unusual
test environments can tune them without code changes. Existing configurations remain valid.

## Diagnostics and event compatibility

During a compatibility wait, the reader stage is
`compatibility_error_backoff`. Stage snapshots retain the existing machine-readable name,
and terminal output renders a Chinese label. Duration telemetry records the actual wait
under a dedicated aggregate metric. Existing error samples and summaries already preserve
the original connector errno, message, SQL, seed, endpoint, and evidence; they remain the
source of the exact server rejection.

No per-error extra event stream is added because it would amplify the same high-rate failure
being contained. Existing `fuzz_error_sample`, `fuzz_operation_error`,
`fuzz_error_summary`, and `fuzz_stage_snapshot` event schemas remain compatible except for
the newly observable stage/metric names.

## Testing

Development follows test-driven changes:

1. Assert that the packaged default asset is named for 8.0.22 and contains no
   `INTERSECT`/`EXCEPT`, restricted random SELECT modifiers, or forced
   `utf8mb4_0900_ai_ci` predicate.
2. Assert that legal `VALUES ROW(...)`, `TABLE`, and `UNION` grammar branches remain.
3. Assert that `RandomGrammarQueryGenerator` forwards excluded families and that both fuzz
   construction paths exclude JSON, FULLTEXT, and SPATIAL.
4. Exercise seeded generation over representative fuzz schemas and reject any forbidden
   token in the generated SQL.
5. Unit-test errno extraction, exponential cap, reset behavior, stop-event interruption,
   and the explicit absence of backoff for `1205`, `1213`, `1690`, and timeouts.
6. Assert the new stage and duration metric appear in snapshots and the Chinese progress
   label renders correctly.
7. Run focused generation/config/fuzz tests, static analysis, the complete test suite, and
   the project build before committing the implementation.

## Release and rollback

The implementation is committed to the current feature branch, pushed, and used to trigger
the existing GitHub Actions build workflow. The distributable contains only the 8.0.22
canonical grammar asset.

Rollback is a normal Git revert of the implementation commit. No database migration or
artifact conversion is required; existing replay records continue to carry their recorded
SQL and grammar hash.
